# Evidence behind the rules

Each rule in `SKILL.md` traces to at least one of the sources below. Research
date: 2026-09-24. Numbers are quoted from the source; caveats are the
source's own unless marked otherwise.

## Rule: route at sub-agent boundaries, not by swapping the main-loop model

- Prompt caches are per model. A commenter on Claude Code issue #27665
  (warku123, 2026-05-13): "switching models mid-conversation invalidates the
  cache entirely, and the whole history gets re-billed at full input rate on
  the new model ... A few switches in a 50K-200K token session and the router
  loses money vs. fixed-Opus." Field data in the same issue: on a Max plan,
  Opus took 93.8% of tokens and 97.8% of cost, and 96% of those Opus tokens
  were cache reads.
  https://github.com/anthropics/claude-code/issues/27665
- Claude Code has no automatic main-loop routing; the only cost levers are the
  sub-agent `model` parameter or frontmatter, `CLAUDE_CODE_SUBAGENT_MODEL`,
  `/model`, and `opusplan` (same issue, from the decompiled CLI).
- The Claude Code docs list "Control costs by routing tasks to faster, cheaper
  models like Haiku" and "Isolate high-volume operations" (test runs, doc
  fetches, log reading) as explicit purposes of sub-agents.
  https://code.claude.com/docs/en/sub-agents
- Changing effort mid-session also invalidates the prompt cache (docs warning).
  https://code.claude.com/docs/en/model-config

## Rule: plan and accept on the frontier model, execute on medium

- `opusplan` in Claude Code: Opus in plan mode, automatic switch to Sonnet in
  execution mode, "pairs Opus's reasoning for planning with Sonnet's
  efficiency for execution". https://code.claude.com/docs/en/model-config
- Splunk (2026-07-15): frontier model for planning and high-consequence
  decisions (short prompts, few calls); cheap models process most of the token
  volume. "The same drop [in quality] can be disastrous during a planning
  phase, where one weak decision sends the rest of the session down the wrong
  path."
  https://www.splunk.com/en_us/blog/artificial-intelligence/reduce-agent-cost-by-model-routing.html
- Minions (Stanford 2025, via Splunk): a frontier model that decomposes work
  into focused sub-tasks for a small model kept 97.9% of frontier quality at
  5.7x lower remote cost; naive small/frontier chat got 30x savings but only
  87% quality. Routing works alongside decomposition, not instead of it.

## Rule: escalate up only, on a verified failure; never retry the same tier

- better-model (talkstream): "On Sonnet failure, escalate to Opus 4.7 -- don't
  retry Sonnet at higher effort. A stronger model at lower effort outperforms a
  weaker model at higher effort." https://github.com/talkstream/better-model
- Issue #27665 (stefmf, 2026-09-03): prompt-time classifiers miss "the task
  turning out to be different than it looked"; escalate on "how many attempts
  have failed, whether the change touched twelve files instead of one, whether
  the tests keep coming back red"; "escalating early is often cheaper than five
  failed cycles on a weaker model."
- Cascade routing (ETH Zurich, arXiv 2410.10347): beats pure routing by up to
  14% AUC on SWE-Bench, but "without post-hoc estimation the effectiveness of
  cascading strategies is severely limited". Tests are the post-hoc estimator;
  this is why every unit needs a mechanical acceptance check.
  https://arxiv.org/abs/2410.10347
- FrugalGPT (arXiv 2305.05176): cascades matched GPT-4 with up to 98% cost
  reduction on short classification tasks, but the cheap attempt is paid even
  when escalating, so a cascade that escalates often costs more than routing
  correctly up front. https://arxiv.org/abs/2305.05176
- LLM-router survey (Bhavsar, 2026-07-28), citing TwinRouterBench: "the
  information needed to route well is generated by execution rather than
  available before it"; a cheap model that "retries several times, accumulates
  additional context, fails validation, escalates to a stronger model" can cost
  more per completed task. https://pakodas.substack.com/p/llm-routers

## Rule: classify by step type with a cheap classifier; ties go up

- Splunk: "Your code already knows whether it is planning, extracting,
  validating, or drafting. That step label is enough to make an initial routing
  decision." Rules "often capture a large share of the available savings";
  learned routers only pay off at high call volume.
- RouteLLM (LMSYS, arXiv 2406.18665): 85% cost reduction on MT-Bench at 95% of
  GPT-4 quality, but routers trained on chat data performed "at a near-random
  level" on out-of-distribution MMLU queries. Coding-agent turns are far from
  the chat distribution, which is why this skill classifies by unit type and
  escalates on evidence rather than trusting a learned prompt-level router.
  https://github.com/lm-sys/RouteLLM
- Routing plateau (Bhavsar, citing arXiv 2606.07587): generic prompt-level
  routing "saturates well below its ceiling and adding classifier capacity does
  not close the gap". Spending frontier tokens on the classification itself is
  therefore waste; Sorcar's `decide()` is a non-generative call.
- claude-model-router (edagher92-coder): "doubt routes up, never down".
  https://github.com/edagher92-coder/claude-model-router

## Rule: measure cost per accepted task and keep a ledger

- Splunk: "A model can cost 80% less per call and still lose money if it
  triples failure-rate or sends more work to human reviewers." Procedure:
  replay a sample of one step on the cheaper model, compare acceptance rate,
  retry rate and total cost, move the step only if cost per accepted task
  falls.
- better-model's measured field data (44,319 sub-agent calls before, 1,266
  after): Opus share moved only from 52.7% to 46.1% when routing relied on
  agent names; savings were 5-10% in plan-mode sessions and 15-30% in
  sub-agent-heavy loops. Routing pays in proportion to how much work is
  delegated, which is why Step 1 of the skill is decomposition.

## Rule: bound the scope of cheap sub-agents

- Composio (2026-05-29): sub-agents "tend to wander off"; bound the prompt
  ("Inspect only src/auth and tests/auth. Return max 15 bullets ... No broad
  repo scan"). The same post ranks output filtering (`| grep -E "FAIL|ERROR" |
  head -100`) as the largest single saver, ahead of model choice.
  https://composio.dev/content/ways-to-cut-token-consumption-in-claude-code
- Claude Code docs: sub-agent descriptions above roughly 15,000 tokens trigger
  a startup warning because descriptions are paid on every turn.

## Rule: effort is a routing axis

- Claude Code docs: `low` for "short, scoped, latency-sensitive tasks that are
  not intelligence-sensitive"; `medium` "reduces token usage for cost-sensitive
  work"; `max` "has diminishing returns and is prone to overthinking".
  https://code.claude.com/docs/en/model-config
- Artificial Analysis cost-per-task: Opus 5.5 at `low` $0.55 per task (index
  42) against $5.98 at `max` (index 58). https://artificialanalysis.ai/

## Existing skills reviewed (why a new one was written)

No widely adopted standalone skill exists for this purpose. On skills.sh the
top relevant entry has 745 installs (`intelligence-route` in ruvnet/ruflo, a
thin wrapper over that project's MCP hooks); the highest-ranked "model router"
hit (456 installs) is about mental models. GitHub repositories dedicated to the
topic have 0 to 3 stars: talkstream/better-model (installer that injects
`model:` frontmatter, measured -18% cost in its own economics model),
arturseo-geo/token-optimizer-skill (static table plus prompt-caching advice),
Laki-private/delegate-to-lower-model (delegates only fixed-spec,
machine-verifiable work), nguyenthienthanh/aura-frog `model-router` (prints a
recommendation but never dispatches). Vex (yusufdxb/vex), which reported
28-55% savings with a confidence-gated pipeline, has been deleted. None of them
combine a runtime classifier, a priced model catalog, a budget gate,
verified-failure escalation and a decision ledger, which is the set this skill
implements.
