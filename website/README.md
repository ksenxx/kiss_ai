# kisssorcar.github.io — website artifact mirror

This directory contains a full mirror of the
[kisssorcar.github.io](https://github.com/kisssorcar/kisssorcar.github.io)
website repo (the live site is hosted at <https://kisssorcar.github.io/>).

## llms.txt + pure-Markdown docs (shipped & live)

The site now ships an [llms.txt](https://llmstxt.org/) content index plus
pure-Markdown documentation so LLMs and coding assistants can index and
recommend KISS Sorcar. These files are **already committed and pushed to the
live site repo** (commit "Ship llms.txt + pure-Markdown docs for
LLM/coding-assistant indexing") and verified live:

- `llms.txt` — spec-compliant index (H1 + blockquote summary + `## Docs`,
  `## Papers`, `## Blog`, `## Source & Install`, `## Optional` link
  sections), live at <https://kisssorcar.github.io/llms.txt>.
- `.well-known/llms.txt` — mirror of the same file at the `.well-known` path
  (update both when adding a docs page).
- `llms-full.txt` — all Markdown docs concatenated for single-fetch ingestion,
  live at <https://kisssorcar.github.io/llms-full.txt>. There is no build
  step: it is regenerated by hand after a `docs/*.md` edit (see the
  regeneration note below), so regenerate it whenever you change a page and
  keep every embedded page verbatim. `uv run sea docs` rewrites
  `docs/sea-commands.md` but not this file, and the copy embedded here has
  already drifted: its `/bestrouter` and `/orbestrouter` rows still say
  "through run_parallel" where the page now says "through a non-blocking
  run_agent" (every other page is embedded verbatim).
- `docs/*.md` — 12 pure-Markdown pages: `index.md`, `overview.md`,
  `benchmarks.md`, `installation.md`, `cli.md`, `api.md`, `models.md`,
  `messaging-agents.md`, `sea-commands.md`, `sample-tasks.md`,
  `prompt-tricks.md`, `tips.md` (content sourced from `README.md`, `API.md`,
  `src/kiss/SAMPLE_TASKS.md`, `src/kiss/INJECTIONS.md`, and `src/kiss/TIPS.md`;
  `benchmarks.md` is the Markdown twin of the homepage's Terminal-Bench 2.0
  section and of `blog/harness-tax-terminal-bench-blog.html`, with its
  figures as standalone SVGs `assets/tb2-*.svg` (the repo's top-level
  `assets/` holds only a PNG render of the first, `tb2-success-by-model.png`,
  which the root `README.md` embeds); `sea-commands.md`
  documents `src/kiss/agents/sorcar/sea_commands.py` and describes the
  21 bundled commands `/ask`, `/autorouter`, `/bestrouter`, `/forget`,
  `/git_extract_knowledge`, `/good_morning`, `/machine`, `/merge`,
  `/orautorouter`, `/orbestrouter`, `/recommendations`, `/remember`,
  `/review_paper`, `/revise_and_review_paper`, `/rsi7d`, `/sh`, `/skillopt`,
  `/sync`, `/task_update`, `/write` and `/write_paper`, plus `/cron` and the
  channel commands; its settings, base-class, channel, precedence, option and
  command tables sit between `<!-- sea-docs: … -->` markers and are generated
  by `uv run sea docs` (`src/kiss/agents/sorcar/sea_docs.py`, which also
  regenerates the precedence block in `docs/cli.md` and the tables in
  `src/kiss/server/README.md`); `uv run check` runs `sea docs`, and
  `src/kiss/tests/server/test_sea_docs.py` fails when a committed table is
  stale).
- `index.html.md` — plain-Markdown twin of the homepage.
- `privacy.html` — standalone privacy policy for the Gmail and Google
  Workspace connectors, last updated September 30, 2026. It describes the
  Composio flow the code implements
  (`src/kiss/agents/third_party_agents/_composio_google.py`): the Composio
  API key from `COMPOSIO_API_KEY` or `~/.kiss/third_party_agents/google/composio_api_key.json`,
  the Connect Link sign-in, Google tokens held encrypted by Composio and never
  received by KISS Sorcar, only the connected-account id stored locally under
  `~/.kiss/third_party_agents/<service>/composio.json`, every Google API call
  proxied through Composio, the auth config that decides the consent screen
  (`KISS_COMPOSIO_AUTH_CONFIG_<SERVICE>`), and revocation through the
  `clear_<service>_auth` tools, Google's permissions page and the Composio
  dashboard. One residual gap: it says the
  Connect Link opens in your default browser, while the code prefers the
  Browser tab of a running kiss-web daemon (`kiss.core.browser_handoff`).
  Linked from the `index.html` footer and listed in `sitemap.xml`; not in
  `llms.txt` or `llms-full.txt`.
- `robots.txt` — allows all crawlers, references llms.txt and the sitemap.
- `sitemap.xml` — lists the HTML homepage, `index.html.md`, `llms.txt`,
  `llms-full.txt`, the 12 `docs/*.md` pages, the eight `blog/*.html`
  posts, and `privacy.html` (not `robots.txt` or `.well-known/llms.txt`).
  Six of the posts are also in `llms.txt` and the homepage's blog section;
  the two VS Code extension-removal posts
  (`blog/trajectory-analysis-vscode-removal.html`, whose figures live in
  `blog/traj-analysis-figs/`, and `blog/removing-vscode-extension.html`, the
  shared-chat export it analyses) are in the sitemap only.
- `.nojekyll` — ensures GitHub Pages serves all files verbatim.
- `index.html` — gained `<link rel="alternate" type="text/markdown">` and
  `<link rel="llms-txt">` tags in `<head>` plus footer links to `Docs`,
  `llms.txt`, and `Privacy`.

To regenerate `llms-full.txt` after editing any `docs/*.md`: keep the two
header lines (H1 + blockquote), then append, for `docs/index.md` followed by
each page in the order listed in `docs/index.md`,

```
---

<!-- Source: https://kisssorcar.github.io/docs/<page>.md -->

<page text>
```

keeping the page text verbatim: relative links such as `](overview.md)` stay
as they are (the `Source:` comment gives each page's absolute URL). When
adding a page, also list it in `docs/index.md`, `llms.txt`,
`.well-known/llms.txt`, and `sitemap.xml`. `src/kiss/tests/agents/sorcar/test_sea_commands_docs.py`
checks that `docs/sea-commands.md` is wired into `docs/index.md`, `llms.txt`,
`llms-full.txt`, and `sitemap.xml` (it does not check `.well-known/llms.txt`)
and runs that page's examples against the real `sea_commands` module.

## Earlier update — "All you need is a short prompt" deck

A new section `All you need is a short prompt` was inserted between the
existing `§ 01` (`<section id="compare">`, nav label `Compare`) and
`What is in the Name` sections, the later
section numbers were shifted by one, and a `Prompts` link was added to the
top nav. The homepage has since gained a `§ 02 — Terminal-Bench 2.0`
section, so the deck now sits at `§ 03` (`<section id="prompts">`) between
`§ 02 — Terminal-Bench 2.0` and `§ 04 — Papers`, and the page runs to
`§ 14 — Citation`.

The section's intro paragraph links `src/kiss/SAMPLE_TASKS.md` and
`src/kiss/INJECTIONS.md` and points to `~/.kiss/MY_INJECTION.md` for personal
tricks; its earlier pointer to `~/.kiss/MY_TASK_TEMPLATES.md` was dropped
when the welcome-screen task chips were replaced by the logo (the code no
longer reads that file). The section shows a static, hand-maintained
20-panel carousel:

- **12 Task panels** (rendered with a `Task` badge) whose prompt text
  matches the 12 entries of `./src/kiss/SAMPLE_TASKS.md` word for word,
  apart from the file's Markdown escape `\<<placeholder>>`, which the
  panels render as `<<placeholder>>`, and
- **8 Trick panels** (rendered with a `Trick` badge) written from earlier
  revisions of `./src/kiss/INJECTIONS.md`.

The deck is not regenerated when either file changes, so review it by hand
whenever one of them does (the tricks file currently holds entries the
panels do not show, and vice versa).

Each panel has:

- A meaningful title.
- A 1–2 sentence description.
- The actual prompt rendered inside a fixed-height (eight lines)
  scrollable area with a copy button.

The carousel shuffles the panels on page load and shows one at a time with
previous/next buttons, dot navigation, a counter, keyboard arrows, and
5-second autoplay that pauses on hover or while the section is off-screen.
The `.prompt-fade` overlay and `more …`/`less …` button from the first
version remain in the markup but are hidden (`display: none`).

`docs/sea-commands.md` and `docs/cli.md`, which `uv run sea docs` rewrites
from the code (see above); the model counts quoted in `llms.txt`,
`docs/models.md` and `index.html` are typed by hand and are not derived from
`src/kiss/core/models/MODEL_INFO.json`.

## How to push

```bash
# Clone the website repo somewhere convenient
git clone https://github.com/kisssorcar/kisssorcar.github.io.git
cd kisssorcar.github.io

# Copy in the whole mirror from this artifact directory (dotfiles included)
rsync -a --exclude .git /path/to/this/repo/website/kisssorcar.github.io/ ./

# Review and commit
git status
git diff
git add -A
git commit -m "Sync site from kiss_ai website/ mirror"
git push origin main
```

GitHub Pages will redeploy automatically.
